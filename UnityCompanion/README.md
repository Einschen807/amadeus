# 牧濑红莉栖 AI 陪伴程序 · Unity 初版

项目使用本机 Unity 6000.6.2f1。场景为 `Assets/Scenes/Companion.unity`；角色设定放在 `Assets/StreamingAssets/persona.md`。本机存在兼容 E-mote 模型和渲染桥接时，红莉栖使用白衣 B 差分的实时动态立绘；资源缺失或启动失败时回退到现有的静态立绘。静态立绘来自同一模型的完整角色渲染。

## 动态立绘演出

聊天模型为回复的每一句输出 `emotion` 与 `gesture`。字幕出现时切换表情，并叠加一句对应的动作；语音音量继续驱动开闭口。表情支持普通、开心、调侃、不满、生气、伤心、担忧、惊讶、害羞、认真、困倦；动作支持点头、摇头、叹气、思考、移开视线、笑、吃惊、脸红。未知标签会回退到安全的默认演出；没有结构化标签的中文回复按内容做简单推断。每次切换演出会清除上一句的脸红等差分；整轮字幕与语音结束、发送新消息或打断回复时恢复普通表情。非默认演出结束后，E-mote 实时模型用约 0.6 秒把表情与姿态参数动画化地回到模型默认值，不再叠加旧立绘图片淡出。打断后的固定回应采用略带生气的表情与语气，回应结束后也会归位。

模型内置的短促眨眼在帧传输下容易表现为闪烁，现改为程序控制的眨眼：约每 4–8.5 秒一次，经历半闭、闭合、半闭、睁开四段；正在使用闭眼或眨眼表情时跳过自动眨眼。

Windows 构建时，若 `EmoteTest/cache/kurisu0-crossed.psb`、`EmoteTest/FreeMote.NET.dll` 和 `EmoteTest/emotedriver.dll` 已在本机准备好，`ProjectSetup.BuildWindows` 会编译独立的 `EmoteBridge.exe`，并将运行文件与模型复制到 `Amadeus_Windows/Emote/`。Unity 在进程外通过本地命名管道接收 E-mote 实时帧；编辑器运行时可直接使用 `EmoteTest/` 中的桥接。缺少这些本地文件时应用仍可运行，显示静态立绘。桥接依赖 Windows x64、.NET Framework 4.8 和 DirectX 9；模型与第三方运行文件不提交到仓库。

动态帧以 1120×2080 渲染后缩放到手机画面，纹理采用双线性过滤；帧缓冲复用，并按桥接渲染速度连续传输，减少锯齿和不必要的等待。`--smoke-emote` 会检查渲染器能产生非空画面、响应指定的情绪动作、张嘴、眨眼与脸红归位，在用户数据目录的 `emote-checks/` 保存原始渲染帧并记录近期帧率。当前旧版 DX9 驱动对部分头发和衣服纹理仍有细碎瑕疵，需在正式画面中继续目视检查。

## 运行

- 立绘取景已按用户确认的布局固定：缩放为原始基准的 123.36781%，相对位置为 X=-0.02917081、Y=-0.04789683。程序内已移除滚轮缩放、按住鼠标拖动、双击复位和相关设置按钮；Windows 手机内容区固定为 620×923，不允许调整窗口大小。口型动画不受影响。
- 确认参数内置于 `PortraitPose.ConfirmedDefault`，不读写本地布局文件（旧版留下的 `portrait-layout.json` 可删除）。
- 设置、记录与审批面板使用统一的 Amadeus 主题（`AmadeusTheme`）：黑底、铁锈红机身、橙红高光线与青绿信号色，面板嵌在手机屏幕内、露出机身外框；提示条约 7 秒后自动收起。`--smoke-ui-gallery` 会把各界面截图到用户数据目录的 `ui-gallery/`，记录页使用示例对话。

- 打开 `UnityCompanion` 项目并运行 `Companion` 场景；或双击上一级的 `启动Amadeus.cmd`，启动已构建的 Windows 独立窗口。启动页使用 `2463169659` 壁纸包内的原始静态标志图，保留红色手机外框与加载进度；进度完成后立绘淡入主界面。Windows 版隐藏系统标题栏，可拖动手机顶部中央移动窗口；右上角的 `−` 和 `×` 分别用于最小化和关闭。
- 在设置中填写自己的 DeepSeek API Key，点击 T 图标打开独立文字输入窗口。Enter 发送，Shift+Enter 换行；麦克风开关只控制收音。两个开关并排位于底部红色面板内。角色说话时在手机外显示独立白色聊天气泡，文字逐句更新；手机位于屏幕右侧时气泡在左侧，反之在右侧。气泡上下边缘不透明，渐变到中央约 40% 透明。
- 主页保持黑色底色，背景有低对比度方格线与略放大的半透明 `0`、`1`；十一条浅绿光迹沿水平线笔直地从右往左、沿垂直线笔直地从上往下移动，另有少量低亮度荧光噪点缓慢漂移。手机外壳装饰覆盖在角色图层之上，底部红色面板横贯整个窗口并遮住立绘下缘。记录、任务记录与服务状态都在设置中。立绘采用已确认的固定上半身取景。
- 启动时气泡隐藏；历史对话仍保存在记录及模型上下文中。最后一句字幕与语音结束后，气泡保留 3 秒供阅读，然后自动消失；打断或报错时立即收起。
- 文字输入使用独立的 Windows 小窗口，通常显示在主窗口下方并跟随移动；主窗口内不再保留输入区或底部占位。点击 T 图标显示或隐藏输入窗口，隐藏时保留草稿和附件；文本窗口默认关闭，与语音开关互不影响，可同时使用。输入窗口右端的回车图标用于发送，也可以按 Enter；Shift+Enter 换行。主窗口最小化时输入窗口同步隐藏，退出时关闭输入进程。屏幕下方空间不足时会移动固定大小的主窗口；上下都放不下时，输入窗口停靠在手机旁边。
- 从 Windows 文件资源管理器拖入文件时，会显示“将文件拖动至此上传”的半透明遮罩，移出或取消后消失。松开后添加为待发送附件，不自动发送；会显示文字输入窗口，麦克风状态保持不变。支持 PNG/JPEG 图片（最多 25 MiB）以及 TXT、Markdown、CSV、JSON、日志和常见代码文本（最多 1 MiB / 24000 字，建议 UTF-8）。一次添加一个文件，可用附件旁的 × 移除；失败不会覆盖已有附件。不支持 PDF、Office 文档、文件夹或虚拟邮件附件的直接解析。
- 图片仍会缩放到最长边 1280 像素并压缩为 JPEG；文本文件在发送时作为资料提供给聊天模型。添加附件本身不需要 API Key，发送仍需要配置密钥。原生拖放使用 Windows OLE 的进入、离开和放下事件，不仅处理松手后的文件路径。

日常对话、图片理解、游戏截图分析全部调用 `deepseek-flash`。`deepseek-v4-pro` 尚未接入自动任务路由。没有 API Key 时聊天禁用，不产生离线假回复。

## Codex 复杂任务

复杂编程、项目修改、调试，以及需要多步骤执行并生成产物的任务会通过 `delegate_codex` 工具交给本机 Codex App Server。普通聊天和简单电脑操作仍使用 DeepSeek 和原有工具，不需要切换模式。明确的编程执行指令会强制选择委托工具；其他复杂任务由模型根据说明选择。

- 设置 → CODEX：路径留空会从 PATH 和本机 Codex 安装目录查找 `codex.exe`；模型留空沿用 Codex 的默认配置，也可以填写该账号可用的模型 ID。点击「检查连接」查看认证状态；未登录时点击「登录 Codex」在浏览器完成 ChatGPT 登录。
- ChatGPT 登录消耗该账号的 Codex 额度；已有 API 登录按 API 用量计费。DeepSeek 仍承担任务判断和角色回复。程序通过 Codex 管理认证，不复制或显示 Codex 凭据。
- 例如：「帮我写一个 Python 小工具并运行验证」「修复 D:\\Projects\\demo 中的编译报错」「继续上个 Codex 任务，增加导出功能」。新任务默认使用 Agent 工作目录下独立的 `Codex/<任务编号>` 文件夹；修改现有项目时请在指令中明确目录。
- 执行期间显示进度，并提供「停止当前任务」。工作目录之外的目录授权、Codex 请求的命令/文件/权限审批，会在程序内显示。采用 `workspace-write` 和 `on-request`，不会自动开启完全访问。Codex 需要补充信息时会显示输入框。
- 「记录 → 任务」可查看任务要求、工作目录、状态、Codex 任务 ID 和执行报告。输入「继续上个 Codex 任务……」会恢复最近一个已有 ID 的任务。任务保存在 `Application.persistentDataPath/codex-tasks.json`，配置在 `codex-settings.json`，原始会话由 Codex 自行保存。不保证出现在 Codex 桌面应用侧栏。
- 每条消息最多委托一次，单次执行等待上限 30 分钟。取消或断线不会回滚已经产生的文件；未收到停止确认时会明确标为待确认。Codex 未登录或报错时不会暗中改用 DeepSeek 执行同一个复杂任务。若执行后角色回复生成失败，会保留执行器报告，避免重复提交。
- 任务上下文包含当前指令、必要的任务说明及本轮附件，不发送整份人格设定或所有相处记忆。桌面自动化能力仍取决于 Codex 自身安装的工具；接入不等于增加任意鼠标键盘操作能力。

接口依据：[Codex App Server](https://learn.chatgpt.com/docs/app-server)。本次按本机 `codex-cli 0.155.0-alpha.16.4` 生成的协议 Schema 验证，通信使用后台进程的 UTF-8 JSONL 标准输入/输出，不开放网络监听端口。

## Agent 电脑操作

直接输入“打开桌面上的某个 PDF”“搜索某主题的论文”等简单指令。无需切换模式：每条消息都能按需要调用电脑工具；明确的电脑操作请求会要求模型先调用工具，避免直接回复“没有连接设备”。路由分三级：规则能确定的请求直接决定；提到文件、网页、屏幕等对象但句式不明确时，用一次 2.5 秒超时的轻量意图分类，超时或失败回落为普通聊天；生成后若模型仍声称无法访问设备，再强制调用一次工具。Agent 通过 `deepseek-flash` 的工具调用，反复选择并组合一个通用的 `computer_action` 工具，当前可搜索网页和 Crossref 论文元数据、打开网页或本机文件/目录、列目录、读取和写入文本文件，以及运行 PowerShell 命令。复杂任务采用上文的 Codex 委托。

打开网页 URL 后，程序会尝试抓取 HTML 并提取正文供红莉栖阅读；也可让她“读一下刚才打开的页面”，程序会使用保存的上次 URL。需要登录、依赖 JavaScript 渲染或拒绝直接抓取的网站可能读不到正文，程序会说明失败。说“看看我的电脑屏幕里面有什么”时，她会抓取**当前主屏幕**，把压缩后的截图随本轮请求发送给 `deepseek-flash`，依据图片回复。截图只在请求时获取，不持续监视，也不保存到对话文件。其他显示器、不可见窗口以及任意点击和键盘操作仍不属于此截图能力。

相对路径指向 Agent 工作目录，可在设置里点击「打开 Agent 工作目录」查看。读取或列出工作目录以外的文件、打开本机路径、覆盖文件、写入工作目录以外的位置，以及运行命令时，程序会显示具体路径或命令并等待允许。拒绝后 Agent 会收到拒绝结果。一次请求最多执行 12 个电脑操作、进行 9 轮模型调用；涉及多个步骤的任务可能产生多次 API 费用。网页搜索返回标题和摘要，论文检索返回元数据，不代表已经阅读全文。

角色持续性由设定文件和程序共同维持。默认相处语气偏亲近、自然熟悉，没有手动关系阶段；记忆不会改变她的核心性格。用户要求“不要扮演红莉栖”时，程序仍让模型以她的口吻回应；明显的模型自我介绍式回复会被拦下：流式输出时逐句检查，跳出角色的句子在播放前作废；若整轮都被拦下，带纠偏提示重新生成一次，仍失败且用户正要求退出角色时，使用固定的角色内回应。明确询问程序是否为 AI 时，角色会简短诚实回答，同时保持对话语气。短语与模式检查无法保证识别所有形式的脱离角色回复。

API Key 使用 Windows 当前用户的 DPAPI 加密，存储在 Unity 的 `Application.persistentDataPath/deepseek-key.bin`。对话记录和自动记忆以普通 JSON 文本保存在同目录的 `conversation.json`，旁边的 `.bak` 是上一份可恢复备份；点击「记录」可回看。程序最多保存最近 250 轮问答，每次请求发送最近十轮和最多 24 条自动记忆；记忆按本轮用户原话用 BM25 检索（IDF 在记忆库内统计），综合相关度、重要度与时效排序，重要度 ≥ 80 的核心事实保留固定名额。设置页「体验指标」显示首字、首句字幕、首句出声、单段合成等耗时的 P50/P90 以及记忆采纳、角色拦截、路由比例，数据只含数字，保存在同目录的 `metrics.json`。每轮成功对话后，后台再调用一次 `deepseek-flash`，只从用户原话提取值得长期保存的事实或偏好；一次性任务、屏幕内容和网页正文不进入自动记忆。低价值记忆随时间由细节压缩成摘要、核心，再删除；高价值记忆保留。旧版手动填写的称呼与备注会迁移成高价值记忆，旧关系阶段不再使用。图片只随当前请求发送，后续轮次只留文字标记。请求错误时保留输入与附件，原对白不被错误覆盖。角色设定文件在构建后位于 `Amadeus_Data/StreamingAssets/persona.md`，编辑后重启生效。

## 构建与边界

通过 Unity 编辑器运行 `ProjectSetup.BuildWindows`，输出到同级 `Amadeus_Windows`。功能检查包括本机截图、网页正文、记忆压缩/遗忘，并用已保存的 API Key 验证过真实记忆提取和屏幕图片理解调用。自动记忆会增加每轮对话的 API 调用次数；提取失败时保留待处理消息，后续重试。

实现依据：[DeepSeek 图像理解](https://api-docs.deepseek.com/guides/vision/)、[DeepSeek 工具调用](https://api-docs.deepseek.com/guides/tool_calls/)、[DeepSeek JSON 输出](https://api-docs.deepseek.com/guides/json_mode/)、[Crossref API](https://api.crossref.org/)、[Unity UI Toolkit 运行时 UI](https://docs.unity3d.com/6000.0/Documentation/Manual/UIE-render-runtime-ui.html)。

立绘交互回归检查：构建后的程序使用 `--smoke-portrait` 启动，会通过 UI Toolkit 指针事件检查拖动和滚轮无法改变取景、口型动画、默认参数记录和窗口缩放，并在用户数据目录 `fixed-portrait-checks/` 输出截图，然后退出。该模式不会触发后台记忆 API 调用。


## 流式日语语音

普通聊天和工具结果通过 DeepSeek SSE 流接收。文本缓冲优先按句号、问叹号、省略号和换行分句，长段落以约 56 字为上限，优先从逗号等位置断开；小数、英文缩写和 URL 的 ASCII 标点不作为普通句末。超长无间隔串仍会按长度拆分。

一次 DeepSeek 流式回复输出 `{"sentences":[{"ja":"日语","zh":"中文字幕","emotion":"happy","gesture":"nod"}, ...]}`，启用 API 的 JSON 输出约束，并在历史对话之后再次明确传输协议，不再为每句另发翻译请求。解析器收到完整日语字段就交给独立的 TTS 消费者，中文字段生成期间可同时合成；播放会等待这一句的中文字幕配对完整，不显示 JSON 或日语。主聊天流不会等待合成或播放，音频队列最多预取两段。当前中文句子完整显示在对白框，日语播完后切换下一句并同步切换演出；记录和后续对话上下文只保存中文。提示词要求首句中文约 10–20 字、日语尽量不超过 24 字。每轮第一句只切出约 10 字的短首段先合成（优先在“、”处断开），剩余部分合并为常规长度的段落；本机实测首句出声 P50 由 4.68 秒降到 3.46 秒。默认回复一到三句，不为了延续对话追问安排。

设置中的语音区域可启用/停用语音、修改整合包目录、API 地址和模型路径，并设置退出时是否关闭自动启动的服务。默认连接本机 9880 端口，检测 `/openapi.json` 中的 GPT-SoVITS API；WebUI 的 9874 端口不是语音 API。若 API 未运行，从配置目录、`GPT_SOVITS_HOME` 和磁盘根目录的 `GPT-SoVITS*` 目录查找本地整合包，启动 `api_v2.py`，使用独立运行配置加载训练模型。复用已有 API 时会选择设置中的模型，但不会在退出时关闭用户的 API 进程。

本地设置保存在 `Application.persistentDataPath/voice-settings.json`，生成的服务配置是 `sovits-runtime.yaml`。默认模型为本机训练的 SoVITS e8 与 GPT e15；模型文件仍位于 GPT-SoVITS 安装目录。固定日语参考文件在 `Assets/StreamingAssets/Voice/reference.wav`、`reference.txt`。双语回复会增加单次回复的输出 token，但没有逐句翻译的额外网络请求。工具调用和自动记忆仍沿用各自的请求流程。

服务启动并加载模型后，会静默合成一次「おかえり。」以预热推理及固定参考缓存，状态栏显示预热进度。预热音频直接丢弃，不播放、不落盘；同一服务与模型在本次程序运行中就绪后不会每轮重复加载或预热。预热失败不会禁用聊天，首条正式语音仍可尝试合成。冷启动的等待被移到准备阶段，不意味着模型加载时间消失。`Player.log` 中的 `VOICE_WARMUP`、`VOICE_LATENCY caption/tts/playback` 分别记录预热、首句字幕、单段合成及开始播放的耗时（秒，不包含对话内容）。

WAV 响应在内存中解码为 PCM 和 Unity AudioClip。播放结束或打断会停止 AudioSource、销毁 AudioClip、释放 PCM 引用；不会保存聊天语音文件。音量每 40ms 计算一次 RMS，经 Attack/Release 平滑和双阈值判断发声；发声时以约 160–260ms 张嘴、80–120ms 闭嘴的变化节奏模拟口型，连续语音也会开合，静音、停顿与停止时闭嘴。动态立绘直接驱动 E-mote 模型的 `face_talk` 变量；静态回退则使用同一模型导出的开闭口贴图。

发送新消息或在语音模式下说出“别说了”等停止指令会使旧聊天流失效、取消当前 TTS 请求并清空队列。单句 TTS 失败时显示中文一段时间，再继续下一句；API 断开后当前轮剩余句子回退为文字。解析兼容句子数组、嵌套容器、代码围栏及常见语言字段别名。没有字幕配对的语音不会播放；若意外返回普通中文或只有中文字段，则保留文字回复，不把 JSON 协议显示给用户。没有任何可用中文时才提示重试。退出时取消客户端请求、停止播放，并根据设置只关闭由本程序持有的服务进程。取消 HTTP 请求不保证第三方 API 会立即终止 GPU 上已经开始的计算；复用用户服务时程序不会为取消一句话而关闭它。

自动检查：`--smoke-speech` 使用 `.codex-integration/speech_mock.py`（本机 18990 端口），验证 UTF-8 分块流、URL/小数分句、首句早于完整流播放、失败恢复、取消、闭口和内存释放；`--smoke-voice-live` 用现有密钥及本地模型、完整人格提示词和人工构造的中文历史进行三轮播放验证，不读取或发送用户保存的私人聊天历史，不保存测试对话。两者均自动退出。测试产生诊断日志，不产生语音文件。

## 陪伴模式

设置页的「陪伴模式」开关会把主窗口切换为置顶小窗，布局为 520 × 200 逻辑单位，实际像素按系统 DPI 缩放（125% 时为 650 × 250），位置会夹回不含任务栏的工作区。窗口通过 DWM（`DwmExtendFrameIntoClientArea`）按像素 alpha 合成：通讯面板约 58% 不透明，桌面内容可以透出来，文字带暗色投影保证可读；头像舱完全不透明，从面板上沿探出。窗口区域裁成"头像舱 ∪ 切角面板"的轮廓，轮廓外的点击直接穿透到桌面。这要求使用 D3D11 并关闭 DXGI flip model（由 `ProjectSetup.Configure` 设置）；DWM 合成失败时退化为不透明深色面板。小窗沿用主界面的 Amadeus 机身语言：铁锈红顶带、橙红描边、红色锯齿底护条，头像外有四角取景框和 MAKISE KURISU 铭牌。头像与普通界面共用同一张实时 E-mote 画面，按显示框宽高比裁出头肩，不会变形。说话者名字右侧的青绿色波形使用正在播放的 PCM 音频响度驱动，静音时回到细小的静止信号；对话背景有低亮度缓慢扫描线。小窗可拖动，右上角低对比度箭头返回普通界面；位置会保存。进入时若麦克风原本关闭，会自动开启；退出时恢复进入前的关闭状态。现有语音识别、双语回复分段、GPT-SoVITS 播放和口型继续使用原有流程。语音说出「进入陪伴模式」「陪我打游戏／工作／看视频」或「退出陪伴模式」等指令也可以切换。

程序每 500 毫秒在本机采样主屏幕缩略图并计算变化；有明显变化时，最多每 2.5 秒将一张长边不超过 1280 像素的关键帧发送到 DeepSeek 视觉接口。截图中的陪伴小窗会被遮住。视觉模块只产生场景摘要、事件和重要度；有新鲜屏幕上下文且语音空闲时，普通主动评论每 10～15 秒尝试一次，同一场景的情况未明显变化时，45 秒内不重复触发常规评论，并把近期台词提供给模型及检查相似回复。重要新事件仍可另行触发一次评论。视觉请求期间的新画面只保留最新一张；用户语音提问最多等待 3 秒刷新画面摘要，再交给原有聊天与分段 TTS 流程。截图不会写入文件或对话历史；主动评论只保留当前运行中的近期记录供去重，不写入普通对话历史。

关闭陪伴模式、程序退出、Windows 锁屏或显示器关闭时会停止截图并取消未完成的视觉请求。设置页明确告知截图发送目标。`--smoke-companion` 在不发送桌面图像的情况下检查小窗、本地采样、图片编码和返回普通界面，并在用户数据目录的 `companion-checks` 保存两张本地测试截图；`--smoke-companion-mic` 检查麦克风在进入时自动开启、退出时恢复；`--smoke-companion-vision` 只向 DeepSeek 发送程序生成的色块图，验证视觉请求与结构化结果解析。普通模式的既有功能不受影响。

## 麦克风输入与语音停止

右下角的麦克风图标默认关闭，关闭时带斜线，开启时为珊瑚色。点击开启后加载本机中文识别模型并开始收音；再次点击只停止收音。T 图标单独控制输入窗口，显示时为珊瑚色 T，隐藏时为带斜线的灰色 T，草稿与附件保留。识别状态可在图标悬停提示或设置中查看。麦克风开启状态不跨程序重启保存。没有设备、Windows 权限不足、加载失败或识别服务退出时会关闭麦克风，文本窗口的显隐状态保持不变。

识别使用 GPT-SoVITS 整合包已有的 Paraformer 中文模型，在 CPU 上通过独立后台进程运行，不占用 TTS 的显存。录音采用系统默认麦克风，内存 PCM 经标准输入传给识别器，不保存录音文件、不上传录音；识别后的文字按原有聊天流程发送给 LLM 并保存到会话记录。首次开启需等待模型加载，关闭收音后模型保留以便再次开启，程序退出时关闭识别进程。

平时停顿约 0.8 秒后自动识别和发送，最长一段约 20 秒。红莉栖回复期间保留收音，以最长约 3.2 秒的片段检测停止指令，普通识别结果不启动新对话。可说“可以，你不要再说了”“别说了”“停一下”“不用说了”“停止回复”等；“不要停，继续说”等否定句不会触发停止。指令需经过采集和识别，识别确认后才会停止当前播放与队列。

原“打断回复”按钮已移除。语音停止后会播放一条固定、成对的中日短回应，例如“哼，知道了。不说就是了。”，语气略带不满；不另发 LLM 请求。该回应期间暂停收音，结束后自动恢复。此实现使用语音指令门控，不是声学回声消除；外放与环境声音会影响识别，耳机效果更稳定。

验证入口：`--smoke-microphone` 检查开关显隐、草稿保留、停止指令及静音分段，不打开实体麦克风。`.codex-integration/asr_checks.py` 使用识别模型自带样例检查内存 PCM、中文编码、异常恢复与进程退出，不使用用户环境录音。
